# Processing capabilities and external dependencies

PDFPro's built-in services implement merge/organize, split/extract, remove pages, rotate, crop, add text, watermark, page numbering, signature-image placement, password unlock/protect, fillable forms, PDF repair, text-match redaction, PDF comparison, PDF-to-JPG, PDF-to-Markdown, PDF-to-Excel, local extractive summary, image scan to PDF, basic HTML-to-PDF, plain-text to PDF, and text-to-DOCX export. Text-to-DOCX carries over the editor's fonts, sizes, text formatting, colors, highlights, alignment, spacing, paper size, orientation, margins, background, and page numbers. These built-in tools process content locally on the server.

OCR PDF accepts PDFs up to 30 pages and single JPG or PNG images. Select up to three document languages per run. Tesseract.js recognizes text locally and produces a Unicode searchable layer that can be opened in the editor. English and Malayalam models are bundled. Other [Tesseract language models](https://github.com/tesseract-ocr/tessdata_fast/tree/4.1.0) are downloaded from GitHub on first use and cached under `server/temp/ocr-models`. For an offline deployment, prepopulate that directory with the matching `<code>.traineddata` files. The server sends only model requests to GitHub.

The editor reads UTF-8 text files and UTF-16 files with a byte order mark. Text to PDF uses the server's installed fonts to shape Unicode text. Install fonts for the scripts you expect to export, such as the Noto font families for Malayalam, other Indic scripts, Arabic, and CJK.

Text extracted from PDF-to-Excel is placed in a simple page/text spreadsheet; it does not reconstruct tables. PDF-to-Word uses Adobe PDF Services automatically when server credentials are configured; each conversion uploads the PDF to Adobe for DOCX conversion and OCR. Complex PDFs can still need cleanup in Word. PDF-to-JPG exports one JPG per page in a ZIP. PDF Summary selects sentences from the source text; it is not an AI-generated summary. Text-match redaction rasterizes pages so covered text is removed, which also removes selectable text; inspect the output before sharing it.

Word, Excel, and PowerPoint to PDF use Adobe PDF Services when server credentials are configured, and otherwise use the isolated worker in `converter-worker/`. Adobe receives the uploaded Office file for cloud conversion, and each conversion may count against the Adobe plan. If you cannot send those files to Adobe, leave Adobe credentials unset and use the worker. Start it from the project root with `docker compose -f converter-worker/compose.yaml up --build`; the worker runs as a non-root user in a read-only container with a private network, CPU/memory/PID limits, a conversion timeout, and per-job temporary files. The API connects to `http://127.0.0.1:3101` by default; set `OFFICE_CONVERTER_URL` when the worker runs elsewhere. If the worker is offline, PDF-to-Word converts detected repeating table grids into editable Word tables. Other PDFs start with editable text and append page images to preserve boxes and appearance. The development machine needs Docker Desktop to start this worker.

To enable Adobe PDF Services, create credentials in the [Adobe Developer Console](https://developer.adobe.com/document-services/) and add `PDF_SERVICES_CLIENT_ID` and `PDF_SERVICES_CLIENT_SECRET` to `server/.env`. Keep the secret on the server. When both values are configured, PDF-to-Word uses Adobe Export PDF, and Office-to-PDF uses Adobe Create PDF for DOC, DOCX, XLS, XLSX, PPT, and PPTX files. These conversions upload the source file to Adobe's cloud and may incur Adobe usage; see [Adobe pricing](https://developer.adobe.com/document-services/pricing/) for current plan terms. If credentials are missing, PDF-to-Word stays disabled and Office-to-PDF uses the isolated worker.

PDF-to-PowerPoint creates one slide per PDF page as a JPEG image; slide text is not editable. PDF-to-PDF/A creates a rasterized PDF/A-1b file with an embedded sRGB output intent, so text is not selectable. The PDF library supplies the PDF/A metadata and structural changes but does not certify every source document; run a PDF/A validator such as veraPDF before using the result for regulated archiving. PDF translation still needs a configured translation provider. Creating a DOCX from the text editor does not require the LibreOffice worker.

Compress PDF & Office performs best-effort compression toward a chosen maximum size. High-clarity mode keeps PDF text/vector content and Office images intact, so the requested target may not be reached. Balanced and smallest modes can rasterize PDFs or resize embedded Office images, which can lower clarity; rasterized PDFs also lose selectable text. Legacy DOC/XLS/PPT and exact target guarantees are not supported. Text redaction is rasterized and removes selectable text; check exported pages before sharing. PDF/A validation and cryptographic signing still need dedicated system tools and worker isolation.

Compress Image separately supports JPG and PNG with a target-size choice. Oversized PNGs are exported as JPEG with a white background so the target can be reached without WebP output. High-clarity mode tries the highest-quality output that fits the target, with small dimension adjustments when needed; exact target sizes are not guaranteed for every image.

For production, run document conversion in isolated worker containers with CPU, memory, and time limits.
